# 领榜个人中心原型 · 开发约定

## 工作范围

- 当前项目为 `invitation-code-recreation`。以当前可见页面、可达流程和用户最新要求为准，不将历史方案重新加回页面。
- 仅修改当前项目；根目录其他原型、管理端配置和参考任务文件不在范围内。
- 用户已将当前原型记录为2.0（2026-11-22）。`versions/1.0/` 和 `versions/2.0/` 是完整版本存档，禁止随后续开发清理、修改或重建；新改动只作用于当前工作源码。
- 默认本地预览，不提交、发布或部署，除非用户明确要求。开发者负责启动并核验预览，不将启动工作交给用户。
- 交付简短文字及可用预览链接，不必附截图；内部可以截图验证。
- 清理以实际引用和可达行为为依据，保留条件状态、有效空态、动态生成的类名和设备运行资源。当前说明只记录最终实现，不追加已被覆盖的方案历史。

## 源码和运行时边界

- 业务界面入口为 `src/Prototype.tsx`，样式为 `src/prototype.css`；会员、邀请、抵用券、申请表单分别由同级模块实现。详见 `docs/原型开发与测试说明.md` 和 `docs/需求列表.md`。
- 以下为受保护运行时，不得改写、删除、替换或绕过校验：`src/App.tsx`、`src/main.tsx`、`src/styles.css`、`src/mobile/`、`public/assets/iphone/`、`public/assets/android/`、`public/assets/status/`、`vite.config.ts`、`worker/index.js` 及运行时构建、校验脚本。
- 只有用户明确要求修改手机运行时本身时，才可调整对应文件；验证后更新对应锁定哈希，不得为通过检查而弱化校验。
- 预览或交付前运行 `npm run check:runtime`；`npm run build` 包含该检查、TypeScript、Vite 和静态输出整理。
- `src/mobile/COMPONENTS.md` 是组件与手势契约。保留两套设备预设及状态、键盘资源，即使当前界面隐藏设备切换入口。

## 组件契约

- 保留 `PhoneFrame → KeyboardProvider`，以及手机内的 `StatusBar`、业务内容、`HomeIndicator`、`KeyboardDock`。状态栏时间实时更新，不写死截图时间。
- 当前默认 iPhone 逻辑画布为 440 × 956，外边界直角、无可见机身边框；这是既定预览尺寸，不宣称为 iPhone 18 Pro Max 官方规格。
- 隐藏设备选择器和模拟触点，原生鼠标必须可见。保留既定微信胶囊尺寸及位置。
- 多页流程使用 `FlowStack` / `FlowScreen`，页面头尾使用其 `header` / `footer`，不要另加路由。`headerHeight` 不含设备状态栏；覆盖式 footer 需要内容自行预留底部空间。
- 普通内容使用 `MobileScroll`；固定导航、Tab、悬浮层放在滚动区外。列表的末项须能滚到安全区上方。
- 水平拖动集合使用 `Carousel`，不要自行添加横向滚动、拖动处理或 CSS scroll-snap；不得对 Carousel 设置 `data-scroll-drag="ignore"`。
- 保留滚动拖动后的点击抑制、手机内原生图片拖动抑制。只有必须独占所有方向手势的控件才用 `data-scroll-drag="ignore"`。
- 所有文本输入使用 `KeyboardInput`、`KeyboardTextarea` 或 `MobileTextField`。不要用原生输入替换运行时组件。
- 手机内弹层使用 `BottomSheet`。导航、弹层及关闭附着输入界面之前收起键盘；FlowStack 和 BottomSheet 已处理其内置动作。输入失焦时收起键盘，直接切换到另一输入框除外。
- `MobileScroll` 已避让模拟键盘，不再叠加键盘高度。自定义固定附着层使用 `useKeyboardInsets().bottomInset`；保留 Android 导航区和 iOS home indicator 层级。

## 当前界面约束

- 每次打开或刷新均从个人中心开始，忽略旧 `page` 参数，不自动弹出海报。页面内导航和返回保留。
- 会员与创客中心独立。会员开通后，标识位于有效期左侧，不放在家长标签后。
- 会员介绍与两项权益合为一张卡；获取方式为一张卡中的“直接购买”和“邀请好友”，中间以“或”分隔。月19.9元、年99.9元，方案卡紧凑，价格合入购买按钮。
- 会员邀请区只介绍10人得1个月会员，进度标题为“邀请进度”，剩余人数提示同一行。邀请按钮直接弹海报；奖励记录进入推广中心奖励Tab。
- 推广中心展示统一邀请人数、累计会员月数、累计抵用券金额。用户与奖励为两个Tab，直接显示全部记录，不添加“示例数据”标记或切换入口。邀请用户列表不展示头像和状态标签，仅保留左对齐的姓名、脱敏手机号和注册时间。
- 奖励Tab分会员和可用抵用券；“历史抵用券”另页分已使用、已过期。每张券用途下方显示一行有效期，已使用券另显示使用时间，不增加可用券总金额。
- 所有用户可分享家长、老师、合伙人三类邀请。个人中心推广卡下方保留“邀请老师 / 邀请家长 / 邀请合伙人”三列入口，直接打开对应海报，不增加中间选择页。
- 共用海报弹窗保留三类切换、PNG保存、直接分享演示；不恢复二次分享渠道选择及已删除的提示文案。
- 创客未开通时保留独立推广卡及服务下方“申请加盟”卡；开通时第一排左创客、右推广，卡高150px，不重复显示申请卡。
- 创客与推广标题右侧保留点击引导；创客标题点击只提示“进入创客中心”。推广卡在创客开关前后保持同一白底绿色配色。
- 创客中心、我的服务、推广中心标题统一17px。底部为首页、订单、消息、我的，选中“我的”，仅静态展示。
- 手机外创客演示开关即时切换并同步 `creator=open/closed`，不刷新、不清空申请草稿或会员状态；刷新依据URL恢复创客演示状态。
- 申请加盟包含区域、校园两类海报和表单；姓名、手机号共享，区域和院校各自保留。提交仅演示，不真实发送或自动开通。

## 演示数据与验证

- 10位有效新用户获得1个月会员；每位同时获得2元抵用券；券自获得起30×24小时有效。用户于2026-11-22确认：家长、老师、合伙人均在首次注册成功后计入，不等待报名、入驻审核或加盟完成；手机号唯一、首次有效邀请绑定，后续邀请不覆盖。
- 当前12位演示用户对应1笔会员奖励及12张抵用券；当前会员状态与历史奖励记录互相独立，不因展示历史奖励而自动开通会员。
- 保留会员未开通、有效、已到期；购买确认、成功、客服说明；抵用券可用、已使用、已过期及空态；两类申请草稿与校验。
- 清理后构建、检查运行时完整性，并回归受影响的页面、弹窗、返回和窄屏布局。不要仅按静态类名搜索删除动态样式。
- 没有真实支付、微信发送、邀请归因、发奖、抵扣核销、客服或申请提交；说明须区分演示与已接入功能。
- 只有明确要求发布时才验证 Sites 交付：确认 `dist/client/index.html`、`dist/server/index.js`、`dist/.openai/hosting.json` 和 `.openai/hosting.json`，运行 `npm run test:sites`。不要替换项目脚手架。

## 原型开发与测试说明

- 说明面板位于手机画布外，默认收起，跟随当前页、Tab、会员状态/方案、海报类型、购买/成功/客服弹窗和加盟校验/提交反馈。浮层说明优先，关闭后恢复来源页说明。
- 宽屏（≥981px）创客演示开关和原型说明入口统一放在手机右侧16px，左对齐上下排列；开关与手机顶部对齐，说明入口在其下方12px。定位跟随手机移动、缩放和说明展开。≤980px采用顶部紧凑控件及下方说明，避免遮挡。
- 单一内容源为 `src/spec/prototype-spec.json`；页面说明、完整HTML、独立Markdown及需求列表同源生成。修改页面、字段、文案、路由或规则时同步数据并运行 `npm run docs:build` / `npm run docs:check`，不要手改生成物。
- 每项需求保留稳定编号、确认依据、实现状态及验收场景引用；原型约定、接口建议、待确认事项不能伪装为已确认生产规则。
- 说明只订阅业务状态，不修改业务值；展开、滚动和阅读说明不应误关手机弹窗或遮挡输入/操作。窄屏在手机区域下方阅读。
- 不在说明重复展示表单完整手机号等个人信息。1.0和2.0存档不修改，本轮说明仅加入当前工作副本。

- 本轮决策：月度会员30×24小时、年度365×24小时，邀请1个月亦30天；续费保留剩余时间。会员退款本期不做，订单退款退券是独立依赖，不据此推导。
- 规则记录维护在JSON的decisions中，仅由完整开发文档与需求列表文档承载；原型说明侧栏只有“当前页面”和“需求列表”两个页签。已确认规则归入对应业务章节，独立文档分别记录确认/采纳/本期不做及剩余联调项。不能把已确认内容继续全部标待确认，也不能将未给出的接口路径或客服渠道伪造成已接通。
- 邀请列表使用服务端完整手机号对应的不透明phoneIdentity去重，phone只作脱敏展示；原型demo-phone键无真实归因功能，不能按展示尾号去重。
